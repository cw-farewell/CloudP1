# 演练记录：服务整体断流（2026-11-18）

## 目的

验证最严重的一类故障：API 副本数归零，服务完全不可用。

重点是看**告警会不会响**。前两场演练都在"服务还活着、只是某个依赖坏了"的范围内，
这一场把服务本身拿掉，正好检验监控有没有盲区。

## 操作

- 注入：`kubectl scale deployment/todo-api -n cloudp1 --replicas=0`
- 观测：集群内探针每秒 `GET /todos`；同时轮询 `/api/v1/rules` 的告警状态和 `count(up{job="todo-api"})`
- 持续：约 3 分钟
- 恢复：副本数改回 2

## 结果：预测成立，两条告警全程沉默

| 时刻 | up 目标数 | 告警状态 |
|---|---|---|
| 10:26:54（注入前） | 2 | 全部 inactive |
| 10:26:56 | — | 探针首次失败（000） |
| 10:27:10 | 2 | 全部 inactive |
| 10:27:25 起 | **无结果**（序列消失） | 全部 inactive，持续到断流结束 |
| 10:29:55（恢复） | 无结果 | 全部 inactive |
| 10:30:12 | — | 探针首次恢复 200 |

探针统计：235 条样本，其中 **199 条失败**，失败区间 10:26:56 到 10:30:00，约 3 分钟。

**用户 100% 受影响，监控一条告警都没发。**

## 为什么会沉默

两条规则都建立在"有数据"的前提上：

- `TodoApiScrapeAvailabilityLow` 用 `avg_over_time(up{job="todo-api"}[5m]) < 0.99`。
  Pod 全部消失后，`up` 系列被标记为 stale 并移出，表达式在空向量上求值，结果是空——不是 0，也不是 1。
  空结果不满足"小于 0.99"，所以不触发。
- `TodoApiHigh5xxRate` 需要请求打进来才有 5xx。副本为 0 时没有后端，请求连应用都到不了，
  计数器不动，比例是空的，也不触发。

一句话：**比例类告警能发现"有数据但不好"，发现不了"根本没有数据"。**

## 修复：补一条 absent 规则

```yaml
- alert: TodoApiTargetsMissing
  expr: absent(up{job="todo-api"})
  for: 1m
  labels:
    severity: critical
  annotations:
    summary: "Todo API 的抓取目标全部消失"
```

`absent()` 的语义正好是"这组序列不存在时返回 1"，填补了比例规则的空缺。

## 修复后的验证

同一操作重跑一遍：

| 时刻 | 事件 |
|---|---|
| 10:34:05 左右 | 注入，副本数改 0 |
| 10:34:40 | `TodoApiTargetsMissing` 进入 pending |
| 10:35:55 | 进入 firing |
| 10:36:0x | 恢复副本数 |
| 10:36:41 | 回到 inactive |

发现耗时约 **110 秒**，和前面 5xx 规则改进后的 89 秒同一量级，符合"抓取间隔 + 评估间隔 + for 1 分钟"的推算。

## 一个需要留意的副作用

Prometheus 自己重启时，目标还没被发现，`absent()` 会短暂成立，规则会进入 pending。
实测重启后 60 秒内自动回到 inactive，因为 `for: 1m` 还没走完目标就回来了，所以没有误报。

**如果哪天把 `for` 调短到 10 秒，这条规则会在每次 Prometheus 重启时误报。** 这个约束要写进注释。

## 三场演练放在一起看

| 演练 | 注入 | 用户影响 | 发现 | 恢复 |
|---|---|---|---|---|
| 依赖故障（Redis） | Redis 副本 0 | 3 秒内 500 | 211 秒 → 改进后 89 秒 | 6 秒 |
| Pod 删除 | 删 1 个 API Pod | 无 | 不需要告警 | 2 秒自愈 |
| 整体断流 | API 副本 0 | 100%，约 3 分钟 | **原配置：永不触发** → 修复后 110 秒 | 约 17 秒 |

规律很清楚：

- **多副本 + 就绪探针能扛住单点删除**，用户无感。
- **单副本依赖一旦挂掉就直接影响业务**，这是当前环境最大的单点。
- **告警必须同时覆盖"有数据但变差"和"没有数据"两种情况**，否则最严重的故障最安静。

## 还没做的

- 两个 API Pod 同时被杀（不是 gracefully scale）没有单独测，效果上接近本场。
- 节点级故障没测，单节点环境测不了。
- 告警仍无通知渠道，"firing"只等于 Prometheus 界面变红。
